# EA9 Windows Updater

Requirements and design: **[spec.md](spec.md)**. Read it before changing anything here.

A single-file Windows GUI (`Community EA9 Firmware Updater v<ver>.exe`, .NET Framework 4.8) that writes the EA9 firmware over USB HID. The release image and `changelog.txt` are embedded in the exe. Before writing, the exe overwrites the lens configuration block in the image (found by its `CfgAnchor` magic) with the user's hardware version and focal lengths / names.

## Prerequisites (Linux)

- ARM toolchain and ASF4 for the firmware build: see the repo README, section 4. The defaults are `~/opt/arm-gcc` and `~/opt/asf4/samd21`.
- .NET SDK 8.x. It is installed in `~/.dotnet`. Set `DOTNET=/path/to/dotnet` to use another one.
- python3.

## Build

```sh
tools/win_updater/build.sh
```

Output: `tools/win_updater/out/Community EA9 Firmware Updater v<ver>.exe`. Ship that one file.

What it does:
1. `make release` in the repo root.
2. `cfgblock.py build/ea9-rebuild-release.bin --out firmware/ea9.bin`: checks that the image holds exactly one lens configuration block, prints it, and copies the image.
3. `dotnet build EA9Updater.csproj -c Release -o out`, embedding `firmware/ea9.bin`, `changelog.txt` and `changelog.zh.txt`.

Before all that it checks that `src/Strings.cs` and both change logs are valid UTF-8, and that `Strings.cs` has a BOM.

If `cfgblock.py` fails, `struct lens_cfg` in `src/lens_cfg.h` changed or its magic appears twice. Update `src/LensConfig.cs` and `cfgblock.py` together. See spec.md 5.

## Common tasks

| Task | Where |
|---|---|
| Edit release notes | `changelog.txt` (English) and `changelog.zh.txt` (Chinese), UTF-8, then rebuild |
| Change or add a text in the window | `src/Strings.cs`: each text in English and Chinese. Save as UTF-8 with BOM |
| Bump firmware version | 0x07 template byte in `src/emount_packets.c` (BCD) **and** `Firmware.DeclaredVersion` in `src/Firmware.cs` |
| Change focal range, defaults or name rules | `LensConfig.cs` (`FocalMinMm`/`FocalMaxMm`, `DefaultName`, `CheckName`, `FromForm`); keep `spec.md` 5.3 in step |
| `struct lens_cfg` changed in the firmware | `LensConfig.cs` (`Encode`, sizes) and `cfgblock.py` (`pack`, sizes) |
| Change the UI | `src/MainForm.cs`. The layout is written in code; there is no designer |
| Look at an image's configuration block | `python3 -I tools/win_updater/cfgblock.py build/ea9-rebuild-release.bin` |

## Files

| File | Content |
|---|---|
| `spec.md` | requirements, patch-table contract |
| `cfgblock.py` | release check of the image's configuration block; reference encoding |
| `build.sh` | make release + cfgblock.py check + dotnet build |
| `EA9Updater.csproj`, `app.manifest` | net48 WinExe, no `.exe.config` |
| `src/Hid.cs` | Windows HID via P/Invoke (`hid`, `setupapi`, `kernel32`) |
| `src/Flasher.cs` | bootloader protocol; mirrors `tools/ea9flash.py` |
| `src/Firmware.cs` | embedded resources, finds and checks the configuration block, patches it |
| `src/LensConfig.cs` | form → normalised slots → block bytes (must match `pack()` in `cfgblock.py`) |
| `src/MainForm.cs`, `src/Program.cs` | UI; `Program` picks the language from Windows |
| `src/Strings.cs` | every text the user sees, English and Chinese |
| `src/HelpPage.cs`, `assets/hw_version.jpg` | the "How to choose?" help pages; the picture is embedded |
| `firmware/` | generated by `build.sh`, git-ignored |
| `out/`, `bin/`, `obj/` | build output, git-ignored |

## Testing

There is no Windows in the build environment. Logic that does not touch Windows APIs (`Flasher.cs`, `Firmware.cs`, `LensConfig.cs`) can be tested on Linux. Compile those files into a .NET 8 console project, together with `Hid.cs` for the `IReportChannel` interface. Drive `Flasher` with a fake `IReportChannel` that plays the bootloader. Compare `LensConfig.Encode()` output against `cfgblock.pack()`.

### UI under Wine (layout smoke test)

Wine runs the exe on Linux using wine-mono in place of .NET Framework. Use it to check that the window opens and the resources load. A broken image makes the status line say "This updater is damaged". Fonts, button styles and the progress bar look different from Windows, so judge the final look on Windows.

One-time setup (Ubuntu). A separate prefix keeps `~/.wine` untouched:

```sh
sudo apt install wine winetricks
export WINEPREFIX=~/.wine-ea9
WINEDLLOVERRIDES="mscoree,mshtml=" wineboot -i     # create the prefix, skip the mono prompt
curl -LO https://dl.winehq.org/wine/wine-mono/9.4.0/wine-mono-9.4.0-x86.msi
wine msiexec /i wine-mono-9.4.0-x86.msi /qn        # 9.4.0 is the version Wine 10.0 expects
```

Run:

```sh
WINEPREFIX=~/.wine-ea9 wine "tools/win_updater/out/Community EA9 Firmware Updater v2.0.0.exe"
```

Screenshot without a desktop (e.g. for an agent): start a virtual display, run the exe there, and grab it:

```sh
sudo apt install xvfb
Xvfb :99 -screen 0 1280x900x24 &
DISPLAY=:99 WINEPREFIX=~/.wine-ea9 wine "tools/win_updater/out/Community EA9 Firmware Updater v2.0.0.exe" &
python3 -c "from PIL import ImageGrab; im=ImageGrab.grab(xdisplay=':99'); im.crop(im.getbbox()).save('ui.png')"
```

Under XWayland, `ImageGrab` on the real display fails (`X get_image failed`), so use Xvfb.

Wine has not been used to test the HID path. Its USB HID passthrough depends on the Wine version and configuration. Do not flash a real adapter through Wine: a transfer cut halfway bricks the adapter until it is recovered over SWD.

### Real hardware

The HID layer can only be trusted on Windows, with the adapter on USB (not on a camera).
